## Автоматическая проверка

CPython 3.11.14, DuckDB 1.4.2, PyArrow 17.0.0, psutil 5.9.8.

11 новых тестов проходят. Они проверяют реальный HTTP Range сервер, чтение и
проекцию вложенных полей Parquet, research/core, возобновление без повторного
скачивания завершённых шардов, прерывание между публикацией usage/events,
целую пару под побайтовым лимитом, выявление разрывов и lifecycle-остановок,
повреждение результата, временно оборванный HTTP-ответ, отказ выполнять Range,
разные файловые системы, недостаток места и принудительную остановку по RSS.
Отдельно пройден standalone CLI через супервизор, освобождение staging после
SHA-256 проверки, повторный CLI-запуск после очистки и настоящий проектный бэктест.

Общий набор: **89 passed, 1 deselected**. Исключён только существующий
`tests/test_deployment.py::test_no_network_or_paid_execution_defaults`:
в исходном commit notebook 01 содержит `CONNECT_GOOGLE=True`, тогда как тест
ожидает `False`. Полный запуск до исключения показал этот единственный сбой.
Notebook и этот тест в патче не изменены.

Команда проверки, с временными файлами вне каталога репозитория:

```sh
python -m pytest -q \
  --deselect tests/test_deployment.py::test_no_network_or_paid_execution_defaults \
  --basetemp=/path/outside/repository/http-tests
```

## Живое чтение публичных источников

Без Authorization/OAuth, только HTTP Range с фиксацией поколения объекта,
проверкой 206 и Content-Range, последующим чтением Arrow и локальным SQL DuckDB:

| Первый шард cell a | Строк в footer | Получено байтов | Проверка первой порции |
|---|---:|---:|---|
| instance_usage | 626337 | 8878132 | 1024 строки, average_usage.cpus читается |
| instance_events | 998903 | 11043533 | 1024 строки, resource_request.cpus читается |
| machine_attributes | 1702926 | 7611046 | 1024 строки, time читается |

Для usage/events использована core-проекция; для machine_attributes — все поля.
Эта проверка подтверждает работу на настоящем формате источника, а не полноту
всего опубликованного экспорта и не отсутствие пропусков в исходном трейсе.

Полный месячный запуск на 25 000 инстансов, его пиковый размер БД и длительность
на пользовательской сети **не измерены**. Размеры порций, сортировка группами,
лимиты памяти/временных файлов и внешний супервизор ограничивают ресурсы;
при достижении защитных порогов job сохраняет checkpoint и приостанавливается.
