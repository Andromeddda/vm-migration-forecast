# Проверка параллельной HTTP-загрузки — 16 ноября 2026

База патча: `fix/combined-cohort-usage`, commit
`3a731dd099f1d5cf782f2ea7c2fbfa2867a4a06e`.

Добавлены два сетевых потока, ограниченная очередь, один обработчик/писатель DuckDB,
отдельные времена загрузки/обработки/checkpoint и корректный счётчик внутри этапа.
Схемы таблиц и формат checkpoint версии 1 не изменены; новые ключи конфигурации
относятся к операционным и не требуют новой сессии.

## Регрессии prefetch и resume

- Детерминированная проверка двумя потоками: первая загрузка ждёт начала второй,
  а третья заканчивается, пока потребитель ещё держит первый шард. Одновременно
  существуют максимум три разных cache-файла; четвёртый не стартует до освобождения
  слота. Выдача потребителю остаётся в исходном порядке.
- Отключение prefetch: пока обрабатывается первый шард, второй ещё не загружается.
- Остановка очереди будит сетевой поток, ожидающий повторной попытки.
- Ошибка посередине обработки откатывает строки и отметку done; предварительно
  скачанные преемники не становятся завершёнными. Повторный прогон даёт точное
  ожидаемое число строк. DuckDB вызывается только в потоке потребителя.
- Старая БД/старый config без новых ключей подхватываются через настоящий CLI;
  завершённый prefix-шард не скачивается заново и его запись done не меняется.
- Последовательный и параллельный режимы дают одинаковые Parquet-таблицы.

Отдельно, вне регрессионной имитации, **исполнен настоящий исходный код из 3a731dd**:
его prefix-прогон прерван перед вторым шардом маленькой HTTP-таблицы. В БД осталось
18 prefix-строк и одна запись done. Новый CLI продолжил эту же сессию до 36 строк
и двух prefix-checkpoint, сохранил первую запись done без изменения, выпустил
датасет из трёх инстансов и успешно проверил его SHA-256. Старый config автоматически
получил новые операционные параметры.

Полный набор: **95 passed, 1 deselected**, включая **17 HTTP-тестов**. Исключение
то же, что описано ниже: существующий тест ожидает CONNECT_GOOGLE=False, тогда как
в исходном commit ноутбук сохранён с True. Ноутбук и этот тест не изменены.

Полный многосуточный прогон и коэффициент ускорения на пользовательском ПК не
измерены. Дополнительные зависимости не нужны.

# Предыдущая проверка HTTP-экстрактора — 13 ноября 2026

База: `fix/combined-cohort-usage`, commit
`faa03b213063b6349bd7d90fc21443cb73a329cf`.

## Автоматическая проверка

CPython 3.11.14, DuckDB 1.4.2, PyArrow 17.0.0, psutil 5.9.8.

11 новых тестов проходят. Они проверяют реальный HTTP Range сервер, чтение и
проекцию вложенных полей Parquet, research/core, возобновление без повторного
скачивания завершённых шардов, прерывание между публикацией usage/events,
целую пару под побайтовым лимитом, выявление разрывов и lifecycle-остановок,
повреждение результата, временно оборванный HTTP-ответ, отказ выполнять Range,
разные файловые системы, недостаток места и принудительную остановку по RSS.
Отдельно пройден standalone CLI через супервизор, освобождение staging после
SHA-256 проверки, повторный CLI-запуск после очистки и настоящий проектный бэктест.

Общий набор: **89 passed, 1 deselected**. Исключён только существующий
`tests/test_deployment.py::test_no_network_or_paid_execution_defaults`:
в исходном commit notebook 01 содержит `CONNECT_GOOGLE=True`, тогда как тест
ожидает `False`. Полный запуск до исключения показал этот единственный сбой.
Notebook и этот тест в патче не изменены.

Команда проверки, с временными файлами вне каталога репозитория:

```sh
python -m pytest -q \
  --deselect tests/test_deployment.py::test_no_network_or_paid_execution_defaults \
  --basetemp=/path/outside/repository/http-tests
```

Без Authorization/OAuth, только HTTP Range с фиксацией поколения объекта,
проверкой 206 и Content-Range, последующим чтением Arrow и локальным SQL DuckDB:

| Первый шард cell a | Строк в footer | Получено байтов | Проверка первой порции |

Для usage/events использована core-проекция; для machine_attributes — все поля.
Эта проверка подтверждает работу на настоящем формате источника, а не полноту
всего опубликованного экспорта и не отсутствие пропусков в исходном трейсе.

Полный месячный запуск на 25 000 инстансов, его пиковый размер БД и длительность
на пользовательской сети **не измерены**. Размеры порций, сортировка группами,
лимиты памяти/временных файлов и внешний супервизор ограничивают ресурсы;
при достижении защитных порогов job сохраняет checkpoint и приостанавливается.
