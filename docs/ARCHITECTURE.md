# Границы и решения

| Слой | Ответственность | Зависимости |
|---|---|---|
| Domain: `core`, `signals`, `allocators`, `synthetic` | Workload, симуляция, сигналы и размещение | NumPy/pandas; без OAuth, CLI и файлов конфигурации |
| Use cases: `experiments` | Серии, идентичность run, повторное использование проверенных результатов | Domain + файловый адаптер |
| Adapters: `google2019`, `data`, `reporting` | BigQuery, подготовка trace, Parquet/NPZ, графики/HTML | SDK и файловая система |
| Configuration: `settings` | Проверка внешних значений, XDG-пути | Только standard library, без I/O на import |
| Composition: `deployment/cli.py`, `lab` | Provision, ADC, диагностика, процесс Jupyter | uv/gcloud; domain не зависит от launcher |
| Notebook | Вызов готовых use cases и интерпретация результатов | Установленное окружение и Settings |

Сохранена исследовательская семантика исходного domain. Это практическое разделение
ответственностей, а не заявление о полной hexagonal-архитектуре: persistence run
пока реализован непосредственно в experiments. Извлекать десятки интерфейсов ради
единственного файлового backend сейчас нет пользы.

GRASP: информация о входных проверках находится у Settings/ExtractionConfig;
контроллер CLI координирует внешние инструменты; бэктестер отвечает за порядок tick.
SOLID: запуск, конфигурация, авторизация и расчёт не смешаны; signal/allocator можно
заменить через существующие контракты predict/choose без изменения notebook setup.
BigQuery client внедряется в BoundedExtractor, что позволяет проверять бюджет fake
клиентом. Настройки неизменяемы; нет singleton с токенами или скрытой авторизации.

Зависимости закреплены старым универсальным uv.lock и устанавливаются полностью
при provision. Пакет не устанавливается editable: PYTHONPATH подключает src,
предотвращая появление egg-info в исходниках. Lazy exports позволяют импортировать
Settings до установки NumPy. Внешний kernelspec указывает абсолютный путь конкретного
управляемого Python, но этот локальный путь генерируется на машине участника и
не входит в исходники.

Состояние отделено от кода; поэтому исходники пригодны для передачи через git.
Исследовательские данные — намеренно stateful: их нельзя удалять при перезапуске.
Jupyter работает foreground; терминал получает stdout/stderr и управляет жизненным
циклом. flock предотвращает конкурирующий provision внутри одного checkout.
Данные/venv между разными checkout нельзя намеренно делить без внешней координации.

## Что именно моделируется

Вход — экзогенный demand proxy CPU/RAM, непрерывная фиксированная когорта.
Google average_usage не является наблюдением контрфактического спроса после миграции.
Миграция не меняет исходный ряд; задержка и overhead задаются SimulationConfig.
При duration > 0 нагрузка остаётся на source до завершения, overhead учитывается
как доля capacity endpoint. Это управляемая модель, не калиброванная физическая VM
live migration. HTTP SLA непосредственно не измеряется.

Решения используют history < t; действие влияет на t+1+duration. Initial placement
строится по warmup prefix. Неполнота/перезапуск trace не заменяется нулями.
Опциональный future-complete-case subset явно маркируется survivorship bias.
`violation_rate` — доля перегруженных host-ticks фиксированного парка.
Повторы одного trace не являются независимыми репликами; три synthetic seeds
пригодны для pilot, но не для сильного вывода о превосходстве метода.
