## Обновление существующей установки

```sh
sh lab configure
sh lab prepare
```

Старый `lab.env` читается без потери `state/data/runs` и настройки свободного места.
Три старых облачных ключа только распознаются и игнорируются для совместимости;
облачных полей в Settings и действий с ними больше нет. `configure` удаляет эти
строки при атомарной перезаписи конфигурации. Неизвестные ключи и дубликаты по-прежнему
отклоняются. Обновление окружения выполняется через `uv sync --locked`.

Патч удаляет компоненты из исходников и зависимостей проекта, а не системную
установку CLI или сохранённые аккаунты, которые могут использоваться другими проектами.

## Ограничения среды проверки

Полный `lab verify-notebooks` через Jupyter-ядро не завершился: песочница запрещает
ZeroMQ операции обнаружения сетевых интерфейсов (`Operation not permitted`,
`Kernel died before replying to kernel_info`). Поэтому проверка ячеек без отдельного
ядра не выдаётся за успешную проверку NotebookClient. На пользовательском Linux
нужно дополнительно выполнить:

```sh
sh lab verify-notebooks
```

Один пропуск pytest относится к `systemd-analyze`, который требует отсутствующий
в песочнице `/tmp`. Настоящие systemd user services и блокировка сна здесь не
проверены; watchdog не изменялся. Повторная многосуточная HTTP-выгрузка не выполнялась:
тесты используют локальные HTTP Range fixtures и настоящие Parquet/DuckDB.
